# 20 登录态持久化：关掉再开不用重新登录

> 日期：2026-10-18　项目：`shandong-run-lab`（sdlab）　对照：原版 APK `com.huachenjie.shandong_school` 8.7.7（26101017）

## 0. 结论

每次都要重新登录不是「没做持久化」，而是**做了又被自己删掉**：

| 现象 | 原因 |
|---|---|
| 登录后关掉命令行/窗口，下次启动要求登录 | `App.close()` 调 `client.logout()`，它 `kv_delete("session")`；而 CLI 每条命令结束都会 `close()` |
| 刷新用户信息后 token 消失 | `_save_session()` 整体覆盖，`load_user()` 只带用户字段，把 token 冲成空 |
| 登录时间每次刷新都变 | `loginAt` 每次 `_save_session()` 都取当前时间 |

修复后：登录态写本地库 `kv.session`，进程退出保留，启动后台校验一次；只有用户显式
「退出登录」或服务端返回 `1516`（token 过期）才清。

## 1. 根因证据

1. `sdlab/app.py` 旧 `close()`：

   ```python
   try:
       self.client.logout()
   except Exception:
       pass
   self.stop_mock()
   ```

2. `sdlab/client.py` 旧 `logout()`：POST `account/logout` → `transport.clear_session()`
   → `store.kv_delete(self.kv_token_key)`。
3. `sdlab/cli.py` 中 `login` / `run` / `records` / `status` 等 12 处命令结束都调
   `app.close()`，即每次执行命令都在删会话。
4. 实测：真实库 `/home/ylxc/.local/share/shandong-run-lab/records.db` 的
   `kv.session` 在「`App(...)` 构造 → `close()`」之后由非空变空（只剩
   `loginAt`）；`loginAt` 还是上次的时间，说明写入没问题、是退出时被删。

## 2. 原版行为（对齐依据）

- 登录响应（`auth/loginPassword` 等）里的 `token` / `satoken` 由 `TokenInterceptor`
  与 `hq1` 保存，落在 SharedPreferences；`App` 启动时读出来直接进主页。
- 只有「我的 → 退出登录」会调 `account/logout` 并清本地；**进程退出不登出**。
- 服务端判定过期返回 `code=1516`，客户端才引导重新登录。

## 3. 修复内容

| 文件 | 改动 |
|---|---|
| `sdlab/client.py` | `_save_session(data, touch=False)` 与 `self.user` **合并**：刷新用户信息不冲 token；`loginAt` 只在 `touch=True`（登录动作）时更新。新增 `_persist_user()`（有 token 才落库）。`load_user()` 成功后 `_persist_user()`。`logout(remote=True)`：`remote=False` 只清本地不发请求（供 1516 用） |
| `sdlab/app.py` | `close()` 只 `stop_mock()`，注释写明原版语义。新增 `_restore_session_bg()`：构造时若已登录，起 `sdlab-session-restore` 线程 `load_user()`：`0` → emit「已恢复登录：…」；`1516` → `logout(remote=False)` + 日志「登录已过期，请重新登录」；异常 → 「会话校验跳过」并保留（离线不乱删 token） |
| `sdlab/cli.py` | `info` 增加「登录状态」：`已恢复 <姓名/ID>（上次登录 10-18 19:05）` / `未登录` |
| `web/app.js` | 用户信息卡增加「上次登录」，显示本地时间 |
| `tests/test_session.py` | 新增 5 个用例（见 §4） |

不变的部分：Mock 与真实两套会话仍分键（`session` / `session_mock`），切换模式不会把
真实 token 带到 Mock、也不会把 Mock 会话当真实会话；`account/logout` 的主动退出流程保留。

## 5. 仍存疑

1. 服务端 token 的绝对有效期未实测（只知道过期回 `1516`）；到期后靠 `_restore_session_bg()`
   的校验兜底，用户会看到「登录已过期」。
2. `satoken` 与 `token` 生命周期是否一致未验证；当前两者一起存、一起清。
3. 多设备登录是否会把旧 token 挤掉未验证；若会，旧设备下次启动校验即 1516 并自动清库。
