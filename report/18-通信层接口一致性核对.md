`SignInterceptor` 继承 `ParamsInterceptor`，负责「9 指纹 + sign」；
`EncryptInterceptor` 负责「表单头 + 字段加密 + 表单体转 JSON」。

### 1.2 `ParamsInterceptor`：三种请求走三条路

```java
// huachenjie/sdk/http/interceptor/ParamsInterceptor.java
Object intercept(Chain chain) {
    Request r = chain.request();
    if (r.header("sign") != null)                       // 已签名（km7.j 手动签的那条）
        return chain.proceed(wrapPostRequest(r, a(r, r.headers())));
    if ("GET".equals(r.method())) return d(r);          // ① GET：只改 query
    return e(wrapPostRequest(r, a(r, r.headers())));    // ② POST：按 body 类型分派
}
```

- **① GET `d()`**：把 query 解码成 map → `decorateParams`（9 指纹）→ `URLEncoder`
  重新拼回 URL。**不签名，不加 UA/token 头**。
- **② POST `a()`**：`hq1.f3189a`（token）非空就塞 `Authorization`，
  `hq1.b`（satoken）非空就塞 `satoken`；`wrapPostRequest` 用 `hq1.j` **覆盖 UA**。
- **`e()` 分派**：
  - `FormBody` → `f()`：decorate（9 指纹）→ 重建表单 → `headers(c(...))` 补 `sign`；
  - `MultipartBody` → `g()`：只 decorate，**不签名**；
  - 其它（JSON）→ `h()`：`JSON.parse(body)` → decorate → `zo4.h(map)` 重新序列化
    → JSON body → `headers(c(...))` 补 `sign`。

`c()` 的实现是 `filterHeader("sign", headers, map, getSign(map))`，所以
**所有 FormBody 与 JSON POST 最终都带 `sign`**（除非调用方已经放了）。

### 1.3 `SignInterceptor`：9 指纹 + sign

```java
// huachenjie/sdk/http/interceptor/SignInterceptor.java
void m(Map<String,Object> map) {
    if (!map.containsKey("timestamp"))
        map.put("timestamp", String.valueOf(System.currentTimeMillis() + hq1.f3188a));
    j(map);   // appVersion / buildVersion / appCode
    k(map);   // deviceId / platform / modelName / systemVersion / channel

```

`l()` 的语义是「**键不存在才写**」，所以调用方自己塞的 9 字段优先。
`hq1.f3188a` 是 `syncTime` 得到的服务端时间偏移（`r90.D()`）。

### 1.4 `EncryptInterceptor`：只碰 FormBody

```java
// huachenjie/sdk/http/security/core/EncryptInterceptor.java
Response intercept(Chain chain) {
    Request r = chain.request();
    if (!(r.body() instanceof FormBody)) return chain.proceed(r);   // JSON/GET 直接放行
    return chain.proceed(f(r, headerInfo));
}
```

`f()` 里才 `setApp(seg[0]).setApi(seg[1]).setV(seg[2])`；
URL 形如 `https://api.huachenjie.com/run-front/run/startSunRun_v2`，
pathSegments 去掉前缀后是 `[run, startSunRun_v2]`，因此
`seg[0]=run-front`（`app`）、`seg[1]`、`seg[2]` 才是 `api`/`v` ——
**三段路径才是「模块/接口」，四段路径的 `api`/`v` 是前两段**。

`HeaderInfo` 的默认值：`pv="2"`、`e=""`、`k=""`。`e` 为空串时 `g()` 判定跳过加密；
`@Headers({"e:1"})` 才会写 `"1"`。`l()` 把 `app/api/v/pv/e/k` 一起 put 进头。

之后：`HashMap`（键是 URLDecode 后的字段名）→ `zo4.h(map)` → JSON 字符串 →
若 `e` 不是空/`"0"` 就对 `ENCRYPT_FIELDS` 做 AES 加密 →
`RequestBody.create(MediaType.parse("application/json"), str)` 重发（**无 charset**）。

> 结论：`@FormUrlEncoded` 接口在线缆上是「**value 全为 String 的 JSON**」，
> 而且会带 `app/api/v/e/pv/k`；`@Body` 接口原样发 JSON，只多 9 指纹与 `sign`。

## 三、修复后的实现

### 3.1 `Endpoint` 增加 `form` 标记

```python
class Endpoint(NamedTuple):
    path: str
    v: str
    api: str
    need_sign: bool = True
    method: str = "POST"
    encrypt: bool = False
    form: bool = True          # True=@FormUrlEncoded；False=@Body(JSON)
```

`form=False` 的 10 个接口：`fence_filter`、`upload_record`、`upload_pace`、
`upload_step`、`upload_stride`、`upload_passpoint`、`finish_sun_run`、
`finish_free_run`、`abnormal_finish`、`abnormal_finish_activity`。

### 3.2 `net.py` 的三条通道

```python
def post(self, name_or_path, payload=None, ep=None, need_sign=None, ...):
    payload = dict(payload or {})
    if ep and ep.method == "GET" or str(name_or_path).startswith(("common/getConfig", ...)):
        return self.get(...)                       # ① GET
    ep = ep or EP.get(name_or_path) or ...
    sign_it = True if need_sign is None else bool(need_sign)
    return self._do_post(ep.path, payload, ep.v, ep.api, h5=..., encrypt=ep.encrypt,
                         sign_it=sign_it, form=ep.form)   # ② 表单 ③ JSON
```

`_do_post()` 的固定顺序：**字符串化 → 字段加密 → 补 9 指纹（setdefault）→
序列化（`,`/`:` 紧凑、不转义中文）→ 算 sign**。

### 3.3 新增的方法

```python
client.start_free_run(lat, lng, aim_distance=0, aim_duration=0, aim_calorie=0)
client.query_unfinish_run(sport_type=1)          # {"sportType": "1"}
client.resume_server_run(run_code, sport_type=1) # {"sportType","runRecordCode"}
```

### 3.4 Mock 侧守门

`MockWorld.require_headers()`：POST 必须带 `sign`；带 `e` 头（表单请求）的还必须带
`app`。`do_POST` 里先过这道门再进业务，**本地也能发现「漏签名」回归**。

新增路由：`run/queryUnFinishRun → 空 data`、`run/resume → 回显 runRecordCode + 打卡点`。

`audit_wire.py` 的断言集合：
GET 必须带 9 指纹 query 且无自定义头/无 sign；POST 必须有 sign 与
`Content-Type: application/json`；表单 POST 必须带 `app/pv/k/e/api/v` 且
`app=run-front`、`e` 为 `""` 或 `"1"`、**所有顶层值为字符串**；JSON POST
不得带表单专属头；任何 POST 的 body 都必须含 9 指纹。

## 五、仍未覆盖 / 存疑

| 项 | 说明 |
| --- | --- |
| `captcha/get`、`captcha/check` | 20 个 `*Api.java` 里没有这两个路由，AJ-Captcha 由 H5/WebView 侧发起；本项目保留同源直连 + 滑块算法（`report/13`），属「可用的等价实现」而非源码同源 |
| 表单字段顺序 | Java `HashMap` 无稳定序，`zo4.h` 的键序与 Python dict 序不保证一致；sign 覆盖全串所以不影响校验，但**逐字节回放**会有差异 |
| `multipart` 接口 | 原版有 `MultipartBody` 分支（只 decorate 不签名），本项目目前无上传图片的 multipart 调用（`free/updateUserFace` 等未实现） |
| 未实现接口 | `filterSchoolActivityFence`、`getDefaultBarrage`、`sendBarrage`、`appealRunRecord`、`runVideo`、`stadiumDeductionList`、`listUserReward`、`rank/runProgress`、`huawei/health/*`、`face/*`、`pay/*`、`oss/getToken` 等约 300 个非跑步主链接口；EP 表里保留了 42 个跑步/登录相关项 |
| 环境切换 | `l43.b()` 的 9/11 分支对应不同主机与不同密钥；本项目只实现生产默认（`envCode` 可配，见 `crypto.get_sign(env=...)`） |
