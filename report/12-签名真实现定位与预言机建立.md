### 2.1 修正 JNIEnv 传参（v23）—— 解开 abort 之谜

**report/11 §17/§19 里所有 "abort" 全是脚本 bug**：

```c
// JNI 约定
typedef const struct JNINativeInterface* JNIEnv;   // env 是「指向函数表的指针」
jstring f(JNIEnv* env, jclass clz, jstring json, jint ec);
//        ↑ 第一参数是 env（JNIEnvExt*），不是函数表
```

ART 会 `down_cast<JNIEnvExt*>(env)->GetSelf()`；

```javascript

const table  = envPtr.readPointer();      // ★ 函数表
// 所有 JNI 调用传 envPtr
```

## 五、可复用的预言机（交付物）

```javascript
// 完整可用的 signRequest 预言机（无需 Java 层，速度极快）
Java.perform(function () {
  const envPtr = Java.vm.getEnv().handle;
  const table  = envPtr.readPointer();
  const jni = (i, r, a) => new NativeFunction(table.add(i * 8).readPointer(), r, a);

  const FindClass           = jni(6,   'pointer', ['pointer', 'pointer']);
  const GetStaticMethodID   = jni(113, 'pointer', ['pointer', 'pointer', 'pointer', 'pointer']);
  const NewStringUTF        = jni(167, 'pointer', ['pointer', 'pointer']);
  const GetStringUTFChars   = jni(169, 'pointer', ['pointer', 'pointer', 'pointer']);
  const ReleaseStringUTFChars = jni(170, 'void', ['pointer', 'pointer', 'pointer']);

  const jc = FindClass(envPtr, Memory.allocUtf8String('com/huachenjie/c/HcjNative'));
  const mid = GetStaticMethodID(envPtr, jc, Memory.allocUtf8String('signRequest'),
              Memory.allocUtf8String('(Ljava/lang/String;I)Ljava/lang/String;'));
  const impl = new NativeFunction(mid.add(0x18).readPointer(),   // ★ ArtMethod.data_
                'pointer', ['pointer', 'pointer', 'pointer', 'int']);

  global.sign = function (json, envCode) {
    const js = NewStringUTF(envPtr, Memory.allocUtf8String(json));
    const ret = impl(envPtr, jc, js, envCode || 0);
    const p = GetStringUTFChars(envPtr, ret, ptr(0));
    const out = p.readUtf8String();
    ReleaseStringUTFChars(envPtr, ret, p);
    return out;
  };
});
// 用法：sign('{"probe":1}', 0)  →  108 字符 base64（80 字节）
```

**★ 关键点**：`mid.add(0x18).readPointer()` 就是 `ArtMethod.data_`，
一行代码即可拿到真实现地址，**绕开所有 hook 检测**。

## 七、方法论（本轮新增 4 条，累计 13 条）

10. **ArtMethod 是问清 ART 的最佳切入点**：
    `GetStaticMethodID` → 读 `+0x18 data_`（native 入口）/ `+0x20 entry_point_from_quick_compiled_code_`。
    比 hook 一切地址都直接。
11. **`RegisterNatives` 登记项 ≠ 实际执行项**：
    登记项可能只被"标准 JNI 调用"使用，而 ART 实际走 `ArtMethod.data_`。
    **必须对照两者**才能定位真实现。
12. **「hook 不触发」时改「直接调用」**：
    hook 依赖 ART 的调用路径；直接调用（`NativeFunction`）绕开一切，
    是最强的存在性证明。本会话靠这一手最终拿下签名算法入口。
13. **`abort` / `access violation` 先查 JNI 传参**：
    `env`（JNIEnv*）与 `table`（JNINativeInterface*）相差一次解引用，
    传错必崩，且崩在 ART 内部（无栈信息）。

| 算法是自定义 | ❌ **标准 AES + 标准 SHA-256 + PKCS#7**（常量表逐字节验证） |
