# 「闪动校园」深入分析（二）：加固载荷判定与动态加载插件

- **样本**：`com.huachenjie.shandong_school.apk`（SHA-256 `4e74df34c08cab0f7b5a1903e5dc204d7a0bf69d56e085731191ea0f909dd470`）
- **承接**：[01-初步分析.md](01-初步分析.md)
- **本轮目标**：执行初步报告第 9 节的第一步——静态重建 DEX 头，取回可读的 Java 业务代码

---

## 0. 本轮结论摘要

1. **静态重建主 DEX：未能完成，但已确定原因**。载荷中 `string_ids` 与字符串池是明文且
   100% 自洽（70,145 条），但**其余索引区（`type_ids`/`proto_ids`/`field_ids`/`method_ids`/`class_defs`）
   与该字符串池不自洽**，`map_list` 也被销毁。判定：这是一个**易盾自定义容器**，不是可直接重建的 DEX。
   → 静态取回主 Java 代码需要先逆向 `libnesec.so` 的容器语义。
2. **同时取得了一项更直接的突破**：包内 `assets/` 下的 **7 个「插件包」全部是明文 APK/JAR**，
   内含未加密的 `classes.dex`。已全部反编译（**5,418 个 Java 文件**），这是目前可读代码量最大的一块。
3. 其中包含：**三个签名完全相同、仅包名不同的「马甲」APK**、一份 **伪装成 AIDL 文件的 Base64 隐藏 DEX**，
   以及成体系的广告点击/安装/设备指纹能力（含 `VirtualClickAdSlotInfo` 模拟点击配额）。
4. 本机**无法进行动态脱壳**：无 Android 系统镜像、无 AVD、无 `/dev/kvm`、无连接设备。

## 1. 加固载荷的静态还原尝试（负面结果与证据）

### 1.1 已经确证为明文的部分

| 项目 | 结果 |
|---|---|
| `string_ids` 数组 | 位于容器偏移 `89,340`，共 **70,145** 项；基址唯一确定为 `85,240`（60/60 命中） |
| 全量校验 | 70,145 项**全部**解析为合法 `string_data_item`（100%），内容排序仅有 1 处逆序 |
| 字符串池 | 明文，约 985,017 条长度≥8 的可打印串 |
| 应用自有类描述符 | `Lcom/huachenjie/` 出现 **12,979** 次 |
| URL / 域名 | 794 条（见 `work/urls.txt`） |
| `type_ids` 规模 | 表长 **11,330** 项（紧接 `string_ids` 之后） |

脚本：`scripts/rebuild_dex.py`、`scripts/probe_dex_sections.py`

### 1.2 无法还原的部分与判定证据

| 检验 | 预期（标准 DEX） | 实测 | 结论 |
|---|---|---|---|
| `map_list` 自引用项 | `type=0x1000, size=1, off=自身偏移` | 全载荷 **0 命中** | `map_list` 已被销毁 |
| `type_ids` 内容 | 全部为类型描述符 | 11,330 项中**仅 9,714（85.7%）**为描述符，1,588 项是 `CONTROL_AE_AVAILABLE_MODES`、`Component`、`addFloat` 等成员名或描述符截断形式 | 与该字符串池的映射不自洽 |
| 全载荷范围是否存在完整 `type_ids` | 应有一条 ≥11,407 项的描述符索引递增序列 | 最长仅 **1,645** 项 | 索引区不在明文中 |
| `class_defs` 指纹（`source_file_idx` → `*.java`/`*.kt`） | 应成段命中 | 在载荷中 **0 命中** | 同上 |
| DEX 头区域 | 112 字节、`endian_tag=0x12345678` | 容器偏移 `85,240`–`89,340`（4,100 字节）**全为高熵密文** | 头部区被加密 |

补充观察：`string_ids` 的偏移是 `4,100`（而非标准 DEX 的 `112`），说明该容器在头部与
`string_ids` 之间插入了约 3,988 字节的私有区域——**容器的节区布局与 DEX 规范不同**。

### 1.3 判定与后续可行路径

> 载荷 = **易盾自定义容器**：字符串池与其索引表明文保留，其余索引区与头部被抽取/加密。

取回主 Java 代码的两条路径：

- **路径 A（静态，成本高但可复现）**：逆向 `lib/arm64-v8a/libnesec.so`，定位容器解析与
  索引区解密例程。壳内已解出 `mShellCnt`、`extract_switch_0`、`shell_limit_0` 等开关名，
  可据此定位关键函数。
- **路径 B（动态，成本低但需环境）**：在可 root 的设备/模拟器上，于
  `attachBaseContext` 之后用 Frida dump 内存中的 DEX（`frida-dexdump`）。
  本机当前**不具备**该环境（见 §5）。

### 2.1 三个「马甲」APK：同一签名、同一套代码

`assets/kcbw7.14.10`、`assets/zj7.17.19`、`assets/lywm7.18.20` 是三个**完整的 APK**（含
`AndroidManifest.xml`、`res/`、`META-INF/CERT.RSA`）：

| 项目 | kcbw7.14.10 | zj7.17.19 | lywm7.18.20 |
|---|---|---|---|

| 证书 SHA-256 | `4ab352559a6c3fae1314a5a1ee545ea4698b3c04fae1b4b20e03625f26608004` | 同左 | 同左 |

> 运行时按配置动态加载，用于规避应用商店的静态审核与 SDK 归因。

### 2.2 插件清单声明的权限（以 kcbw 为例）

`INTERNET`、`ACCESS_FINE_LOCATION`、`ACCESS_COARSE_LOCATION`、`ACCESS_NETWORK_STATE`、
`ACCESS_WIFI_STATE`、`READ_PHONE_STATE`、`READ_EXTERNAL_STORAGE`、`WRITE_EXTERNAL_STORAGE`、
**`REQUEST_INSTALL_PACKAGES`**（9 条；`minSdk 17` / `targetSdk 30`）。
虽然插件自身没有组件，但这些权限声明会在宿主加载插件清单时参与合并。

### 2.3 伪装成 AIDL 文件的隐藏 DEX：`assets/stars.aidl`

- 文件实为 **Base64 文本**（`ZGV4CjAzNQ…`），解码后 4,780 字节，magic = `dex\n035`，1 个类。
- 反编译结果：`com.starsads.open.invoke.Adw`，两个方法**全程反射**（`Class.forName` + `Method.invoke`）：
  - `dm(Context, uri, int, byte[])`：构造 `Intent.ACTION_VIEW`，反射调用 `Intent.createChooser`
    与 `Context.startActivity`（带 `FLAG_ACTIVITY_NEW_TASK`）→ **deeplink 拉起外部应用**；
  - `hr(Context, uri, pkg, …)`：把 `{"deepLink":…, "pkgName":…}` 作为 **`ContentResolver.query()`
    的 selection 参数**去查询目标 provider，再从 `Cursor.getExtras().getInt("code")` 判断结果 →
    **通过 ContentProvider 探测/唤醒其他应用**。
- 该文件在 Manifest 中没有任何声明，只能由主代码按文件名读取并 Base64 解码加载。

> 这是典型的「**隐藏能力 + 全反射逃逸静态检测**」手法：把最敏感的跨应用调用原语
> 放到一个伪装扩展名的独立 DEX 里。

### 3.1 关键证据一：广告 SDK 内置「虚拟点击」（模拟点击）能力

`com.kc.bw.ad.dex.allmodules.bean.VirtualClickAdSlotInfo` 的字段直接说明用途：

```java
String adSlotId;
long lastOperationTime;
long lastSimulatedClickTime;   // 最近一次「模拟点击」时间
long lastSlideClickTime;       // 最近一次「滑动点击」时间
int  simulatedClickedCount;    // 模拟点击计数
int  slideClickedCount;        // 滑动点击计数
public boolean isExpired() { return Utils.isNextDay(this.lastOperationTime, "virtualClick"); }
```

配套实现 `...allmodules.utils.pdexs`（JADX 标注 `compiled from: AbsVirtualClick.java`）把计数
按代码位持久化为 JSON，并回传服务端：

```java
com.kc.bw.pdexf.pdexf.pdexa(pdexf, "updateVirtualClickInfo:" + json);
pdexa("更新媒体指定代码位下虚拟点击信息失败(updateVirtualClickInfo):clickType=" + i, th);
```

> 即：**该 SDK 会按日配额对指定广告位执行「模拟点击 / 滑动点击」，并统计上报**。
> 这类行为属于广告点击欺诈范畴，与包内同时存在的无障碍套件、`REQUEST_INSTALL_PACKAGES`
> 构成完整的能力闭环。

### 3.2 关键证据二：广告 SDK 枚举系统无障碍服务

`gdtadv2/…/com/qq/e/comm/plugin/h3.java`（腾讯优量汇）读取
`AccessibilityManager.getInstalledAccessibilityServiceList()` 与
`getEnabledAccessibilityServiceList(-1)`，逐一收集 `AccessibilityServiceInfo.packageNames`
并 `URLEncoder.encode` 后上报。

> 这既是设备指纹/风控信号，也说明**广告 SDK 会感知本机已启用哪些无障碍服务**——
> 与宿主自带的 `com.acse.ottn` 无障碍套件形成呼应。
> 此外 `gdtadv2` 内含 `com.tencent.turingfd.sdk`（腾讯图灵盾设备指纹）。
