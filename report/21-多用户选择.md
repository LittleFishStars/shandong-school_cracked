# 21 多账号选择：选一个登录过的用户直接开跑

> 日期：2026-10-18　项目：`shandong-run-lab`（sdlab）　对照：原版 APK 8.7.7（26101017）

## 0. 结论

在登录卡里加了一个「历史账号」下拉：本机登录过的账号都留在本地库，选中点「使用该账号」
即换 token、刷新用户信息与学校缓存，随后直接拉围栏、开跑，**不需要重新输密码**。
CLI 对应 `sdlab users` / `sdlab users use <id>` / `sdlab users rm <id>`。

原版只有一份登录态（SharedPreferences 单账号），换人要退出再登；这里把会话按 `userId`
存成列表，是桌面端多用户场景的扩展，协议层没有任何改动。

## 1. 存储

| 键 | 模式 | 内容 |
|---|---|---|
| `kv.session` | 真实 | 当前账号会话（token/satoken/schoolCode/userId/loginName/loginAt…） |
| `kv.accounts` | 真实 | 历史账号列表（同上字段，按 `loginAt` 倒序，最多 20 条） |
| `kv.session_mock` / `kv.accounts_mock` | Mock | 同上，两套互不污染 |

去重键是 `userId`：真实服务端同一手机号重登 userId 不变，只更新 token 与登录时间。
`token` 只在本地库，界面层展示时手机号脱敏（`138****8000`）、token 截断。

## 2. 接口

### 2.1 客户端（`sdlab/client.py`）

| 方法 | 说明 |
|---|---|
| `accounts()` | 读历史账号列表（含 token，供后端使用） |
| `_remember_account()` | 登录成功登记当前会话（按 userId 去重、最近在前、上限 20） |
| `switch_account(uid)` | 换会话 → `load_user()` → 成功则刷新该账号的登录时间；`1516` 摘除并回滚 |
| `forget_account(uid)` | 移除历史账号；删的是当前账号则顺带 `logout(remote=False)` |
| `_apply_session(sess)` | 统一把一条会话装进 transport 与 `kv.session` |
| `_reset_school_state()` | 清围栏/学期/规则/公共配置缓存，避免拿上个账号的学校开跑 |

### 2.2 应用层（`sdlab/app.py`）

- `list_accounts()`：脱敏后的列表（`userId/userName/schoolName/loginName/loginAt/current`）。
- `switch_account(uid)`：跑步中拒绝；成功后清打卡点与上一条结果，重拉
  `common/getConfig`、`getSemesters`、`getFences`，失败只记日志不阻断。
- `forget_account(uid)`：跑步中拒绝。
- `status()` 增加 `accounts`，前端一次刷新就能重绘下拉。

### 2.3 界面

- Web 左栏登录卡：`历史账号` 下拉 +「使用该账号」/「移除」两个按钮；登录、切换、移除后
  都 `refreshStatus()` 重绘（下拉保留用户当前选择，其余情况默认选中当前账号）。
- CLI：`sdlab users` 列表（`●` 标记当前账号、显示脱敏手机号/姓名/学校/上次登录/账号 id）。

## 3. 边界与安全

| 场景 | 行为 |
|---|---|
| 跑步进行中 | 拒绝切换/移除，提示先结束 |
| token 已过期（1516） | 切到该账号时自动从历史里摘掉，回滚到切换前身份 |
| 主动退出登录 | 只清当前 `session`，历史账号保留（下次仍可一键切回） |
| Mock 模式 | 历史账号同样登记，但 Mock 服务端每次启动是新实例，旧 token 不认——这是 Mock 的局限，真实服务端正常 |

## 5. 已知限制

1. 真实 token 的绝对有效期未实测；过期后切换会被摘除并提示重新登录。
2. 同一真实账号重复登录会刷新 token，旧 token 是否被服务端立即作废未验证（本地只保留最新一条）。
3. Mock 模式的 token 不跨进程有效，多账号切换的跨进程验证只能在真实服务端完成。
