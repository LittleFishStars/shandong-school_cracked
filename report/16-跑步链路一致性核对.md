## 一、定位采样：一致（3000ms）

**原版** `work/jadx_FULL/sources/com/huachenjie/common/run_component/LocationComponent.java:201`：

```java
lj0.m(this.f8849a, 3000L, this.f8853a, locationMode, true);
```

跑步期间的定位回调间隔写死 **3000ms**。`locationMode` 由 `amapGPSLevel` 选（`:195-200`）：
`1 → Battery_Saving`、`2 → Device_Sensors`、其余 `Hight_Accuracy`；`CommonConfig.amapGPSLevel` 默认 `3`。

容易误读的一点：`work/jadx_FULL/sources/com/huachenjie/common/service/LocationService.java:157-165`
的 `j(long interval)` 里有 `if (interval == 0) interval = 2000;`，**那是常驻定位服务那条路**，
不是跑步采样。`StartLocationEvent(long interval)` 在整个 Java 侧没有任何构造点，跑步链路并不走它。

**本项目** `sdlab/walker.py:58` `SAMPLE_INTERVAL_S = 3.0` —— 一致，无需改。

## 三、轨迹点：三处真偏差（均已修）

### 3.1 `runTime` 单位差 1000 倍

**原版** `DataComponent.java:715` 是唯一定义处：

```java
RunLatLng runLatLng = new RunLatLng(E(), (int) Q0(), currentAddressInfo, outFenceDisM, currentAddressInfo.getTime());
```

`Q0()` 已是整数秒，再 `(int)` 强转 ⇒ `runTime` 是**跑步内相对秒**。
序列化侧 `work/jadx_FULL/sources/com/huachenjie/common/bean/RunLatLng.java:40-41`
`@JSONField(name = "runTime") private int runTimestamp;` 原样上传。

**修前本项目**：`sdlab/walker.py:429` `run_time=int(self.elapsed_sec * 1000)`，`protocol.py` 两处轨迹
生成器同样 `* 1000`，注释也写成「跑步内相对 ms」。

**已修**：三处改为 `int(round(...))`（秒），注释同步；`tests/test_protocol.py`、`tests/test_store.py`
的造点断言改 `i * 3`。

### 3.2 `createTime` 恒发 0

**原版** `RunLatLng.java:199-215`（`W1()` 用的 5 参构造器）：

```java
this.createTime = System.currentTimeMillis();
this.state = 1;
this.offFenceDisM = offFenceDis;
```

`createTime` **没有** `@JSONField(serialize=false)` ⇒ 会上传，值是造点那一刻的绝对毫秒。

**修前本项目**：`protocol.RunLatLng.create_time` 默认 `0`，造点时没传；更隐蔽的是
`store.add_points()` 写库时用 `now` 盖掉了这个字段，而 `_row_to_point()` 读回时不还原
⇒ 库里有值、报文里是 0，两边不一致。

**已修**：造点处补 `create_time=ts`；`store.add_points()` 写 `p.create_time or now`；
`_row_to_point()` 还原 `create_time`。

### 3.3 `offFenceDisM` 语义搞反

**原版** `DataComponent.java:715-742` `W1()`：

```java
if (outFenceDisM >= 0) { jLongValue -= outFenceDisM; i4a.b(g, "离开围栏的距离已删减~~~~"); }
if (jLongValue <= 0) { jLongValue = 0; }
```

即这个字段是「**离开围栏的总距离**」，并且要**从两点间距离里扣掉**——不是「到围栏边的距离」。

它的取值只有两个来源（`work/jadx_FULL/sources/com/huachenjie/run/service/SunshineRunService.java:296-301`）：

```java

else { jV2 = -1; }

```

`B1()`（`DataComponent.java:253-256`）= 缓存里恰好有「出去那一点、还没回来」⇒ **只有刚回围栏那一帧**
才拿到正数。另一条路径 `DataComponent.t2()`（`:1211-1219`）直接硬编码 `-1L`，坐实常态就是 `-1`。

**修前本项目**：`off = int(distance_to_polygon_edge(lat, lng, self.polygon))`，围栏内恒 0
⇒ 语义不对（虽然数值上不参与累距，不会把距离算错，但报文语义是错的）。

### 结算有三条路径，报文不同（2026-10-18 补）

| 路径 | 入口 | 端点 | `runImgRecord`/`timestamp` | 其他 |
| --- | --- | --- | --- | --- |
| 阳光跑 | `km7.c()` → `aw8.c()` | `run/finishSunRun_v2` | **有** | — |
| 自由跑 | `km7.b()` | `run/finishFreeRun` | **无**（不调 `aw8.c()`）| — |
| 异常结束 | `StartRunUtils.o0()` → `StopRunUtils.o()` → `aw8.b()`/`aw8.a()` | `run/abnormalFinishSunRun` / `run/abnormalFinishActivityRun` | **有** | 额外带 `abnormalCodes=[checkData]` |

`aw8.b()` 用于 `sportType == 1`，其余 sportType 走 `aw8.a()`（`StopRunUtils.o()` 的 `Z1` 分支）。
本项目 `client.finish_run()` 用 `abnormal_code` 参数区分三者。

本项目 `client.finish_run()` 按上面的路径分发（`sun` / `abnormal_code` 两个开关）。**有意保留的差异**：

| 差异 | 原因 |
| --- | --- |
| ~~`distance` 发 int~~ | **已修**：原版 `t1()`/`StopRunUtils.q()` 用 `String.valueOf(...)`，现发 String |
| `pauseCount` / `pauseTimes` 恒 0 | 本项目**没有暂停功能**，恒 0 是自洽的；原版取 `getPauseCount()` 是因为它真有暂停 |
| 缺 `cheatList` | 本项目没有作弊检测链路（`HcjNative` 侧），无数据可填 |
| 缺 `abnormalCodes` | 同上，没有「异常退出码」这条路径 |

**`runImgRecord` 已完全攻破**（`report/17-native encodeRun 破解.md`）：

```
runImgRecord = MD5(runRecordCode + versionCode + versionName + KEY(env) + timestamp)
```

`KEY` 按 `env` 三选一（`liby.so+0x1e068` 的分支）：`env ∈ {1,10}` 用第二把、`env ∈ {9,11}`
用第三把、其余用生产密钥。用黑盒预言机 6 组样本逐字节验证 **6/6 全中**。

本项目 `crypto.run_img_record(code, ts, vc, vn, env)` 已改为同一公式，
结算报文里同时补上 `timestamp`（原版 `aw8.c()` 在 `km7.c()` 进 `finishSunRun_v2` 前无条件塞这两个键）。
