## 一、配置从哪来（学校怎么开）

### 1.1 两个下发口

- `CompatApi.i()`：`POST run-front/face/getUserFaceImg` → `UserFaceBean`
- 跑步规则接口（checkRunRule / 开始跑步参数 `StartRunPageParam`）内嵌 `faceCheckData`（`SunshineRunFaceCheckData`），字段更全。

### 1.2 UserFaceBean 字段（`UserFaceBean.java`）

```java
faceEnabled      // 学校是否开启人脸功能
faceImg          // 底库照片 URL（OSS）
similarityValue  // 比对阈值（百分比，如 80）
faceAuth         // 本人是否已完成人脸认证
runRecordCode    // 当前跑步记录（跑中扫脸时非空）
faceTime         // 扫脸倒计时秒数（提示弹窗给多久去扫）
leftTime         // 剩余可用扫脸时间预算
bodyEnable       // 是否加验"人体/活体"
bodyRate         // 活体阈值
faceModelType    // 1=FACE_MODEL_ALIYUN, 2=FACE_MODEL_LOCAL
faceCheckIndex   // 当前是第几个检查点
```

`faceCheckRecordList`（`SunshineRunFaceRecord` 列表）由服务端为每次跑步**随机生成检查点里程**：

```java
checkIndex / randomDistance        // 第几个点 / 在多少米处触发
hasChecked / finishFaceCheck       // 是否弹过 / 是否完成
popTime / checkDistance / checkLng / checkLat   // 弹出时刻、当时里程与经纬度（防"提前找好位置"）
runFaceUpload / runFaceImg         // 是否已传照 / OSS URL
confidence / rate / label          // 比对置信度 / 活体分 / 活体标签
faceRequestId / bodyRequestId      // 阿里云两次调用各自的 requestId
faceCheckErrorCode / bodyCheckErrorCode
extendParam                        // 过程进度串（progressStr）
```

### 1.3 开关与关闭的语义

`UserFaceActivity.java:150`：关闭人脸识别会**删除底库照且本学期不可再传**：
> "确定关闭人脸识别功能吗？关闭后您的人脸照片将会被删除，同时阳光跑将无法进行人脸识别核验会导致跑步成绩无效，且本学期将不再支持上传人脸照片"

## 三、本地比对模式（faceModelType=2，InspireFace 端上识别）

### 3.1 引擎初始化（`FaceTool.k()`）

```java
InspireFace.GlobalLaunch(context, TypeDefine.PIKACHU);          // PIKACHU 模型
session = InspireFace.CreateSession(parameter, 1, 1, 320, -1);  // trackPreview=320
InspireFace.SetTrackPreviewSize(session, 320);
InspireFace.SetFaceDetectThreshold(session, 0.5f);              // 检测阈值 0.5
InspireFace.SetFilterMinimumFacePixelSize(session, 0);

// parameter（lazy，FaceTool$parameter$2）:
CreateCustomParameter().enableRecognition(true)
                       .enableFaceQuality(true)
                       .enableInteractionLiveness(true);
```

包名 `com.insightface.sdk.inspireface` = InsightFace 开源 **InspireFace** SDK（native so），模型 PIKACHU。

### 3.2 帧处理（`FaceDetectAnalyzer.analyze()`）

CameraX `ImageAnalysis.Analyzer`，只收 `format==35`（YUV_420_888）；`FaceTool.f()` 手写 Y/U/V 平面旋转拼接成 NV21 `TrackingInfo`，丢给 `FaceDetectionThread` 处理 `l()`：

1. **底库特征预载**（`i()`）：`faceImg` URL 下载（OkHttp 直连，缓存 `externalCacheDir/FaceRecognitionCache/<md5(url)>`）→ `a(bitmap,false)` 提取 `bgFaceFeature`。
2. **取最佳人脸**（status=0）：质量门槛 `n()`：
   - 人脸面积 / 画面面积 ∈ [0.1, 0.6]，否则「请靠近一点 / 请远离一点」；
   - 人脸中心须落在画面中央 20%~80% 区域（`j()`），否则「请移动到中间」；
   - `FaceQualityConfidence >= 0.5`，否则「请保持不动」。
   满足 → `bestFaceData = (faceResult, trackingInfo)`，日志「获取到最佳人脸」。
3. **活体 = 摇头交互**（`l()` 状态机，`bodyEnable==true` 时才走，否则直接比对）：
   ```
   1 → callback.b() 提示开始;  shake[0]==0 → 状态2「开始摇头检测...」
   2 → shake[0]==1 → 状态3「摇头中...」
   3 → callback.c(); shake[0]==0 → 状态4「完成摇头动作识别」 + setLivenessCheck(1)
   ```
   动作数据来自 `InspireFace.MultipleFacePipelineProcess(...) + GetFaceInteractionActionsResult(session)` 的 `FaceInteractionsActions.shake`。
4. **比对**（`k()`）：`InspireFace.FaceComparison(bestFaceFeature, bgFaceFeature) * 100` → `bestSimilarity` → `callback.a(sim, trackingInfo)` 由 Fragment 按服务端 `similarityValue` 阈值判过不过（日志「置信度通过.../未通过...」）。

### 3.3 结果落盘与上传（`DetectFaceDelegate.x(..., needEncodedFileName=true)`）

`DetectFaceLocalCheckFragment.java:351/557`（失败/成功都传）：

```java

        .setAccessKeyId(STS AccessKeyId)
        .setAccessKeySecret(STS Secret)
        .setSecurityToken(STS Token));
```



## 六、防作弊面观察（供后续对抗参考）

1. **位置绑定**：每个检查点记录 `popTime/checkDistance/checkLng/checkLat`，服务端可校验"扫脸时人是否在轨迹上"。
2. **时间预算**：`faceLeftTime` 全程共享，拖着不扫会耗尽（`updateRecognitionPauseLeftTime`）。
3. **文件名加密**：跑中照 OSS 对象名 RSA 加密，防直接按 URL 规律拉别人照片。
4. **本地模式特征在端上**：阈值 `similarityValue`、活体开关都由服务端下发但**判定在客户端回调里做**（`FaceDetectAnalyzer.k()` 的 callback），意味着修改端上判定即可改变本地模式结果——但照片仍会传 OSS、`confidence` 等证据仍随结算上报，服务端有人工复核兜底。
5. **阿里云模式判定在云上**：confidence 由 facebody 返回，客户端只比较大小，改端上无意义（可伪造的只有上报字段）。
6. **认证照与跑中照目录分离**：`face/user` vs `face/run`，服务端可对 run 目录做一致性风控（如同一照片重复出现）。

## 七、与 sdlab（Python 重实现）的关联

当前 sdlab 走的是无扫脸学校的链路（`faceCheckData.faceAuth=false` 或列表为空时 `faceCheckRecordList` 不触发）。若要支持开启人脸的学校，需要：
1. 结算报文带 `faceCheckRecordList`（字段见 §1.2，需服务端先在 checkRunRule 下发检查点）；
2. 现场照上传 OSS `face/run/<RSA密文名>.jpg`（公钥见 §3.4，可直接复用）；
3. 本地/云端比对二选一：本地模式需 InspireFace 等价实现或直接构造 `confidence` 上报；阿里云模式需 STS + facebody 调用。

本轮为纯静态分析，未改代码；sdlab 无人脸分支，无回归影响。
