核心结论：
1. **我们缺"速度动力学"**：生成轨迹过于匀速完美（CV 0.08 vs 真人 0.24-0.34），且 lag-1 自相关为**负**（-0.23，平滑振荡伪影），真人是强正（0.5+）。这是下一步改进方向（v(t) 单源模型 + GPS 噪声）。
2. **ST 的阳光跑引擎有硬伤**：申报 3000m 时几何轨迹恒为 ~5.3km（步态锁死 104 步/分 × 1.84m，偏离默认配速 315s/km 即失配），且对围栏尺度敏感（官方示例围栏直接退化成 3m 几何）。服务端不交叉核对距离所以能过，但这是它最大的保真度缺口。
3. **muccc526 恒速直线**，最弱。
4. ST 自由跑引擎（generate_trajectory）确实自洽（自检距离误差 0.0），其物理模型思路值得吸收。

## 一、真人基准（实测）

来源：`marcusvolz/strava` 仓库 `inst/gpx/running/` 的 3 条 West Berkshire Running：

| 指标 | 7335911454 | 7371775190 | 7621813676 |
|---|---|---|---|
| 距离/时长/配速 | 7.05km/45.9min/7'31" | 6.72km/42.2min/6'17" | 5.37km/30.3min/6'39" |
| 采样中位 | 4.0s | 5.0s | 5.0s |
| 逐点速度 CV | 0.34 | 0.30 | 0.24 |
| lag-1 自相关 | 0.78 | 0.69 | 0.49 |
| 10s 窗配速 CV | 0.284 | 0.197 | 0.124 |

解读：
- **逐点 CV 0.24–0.34** 里含 GPS 噪声；**10s 窗 CV 0.12–0.28** 是去掉噪声后的真实
  人类配速波动——跑者并不匀速，10 秒窗配速天然有 ±12%~28% 的变化。
- **lag-1 自相关 0.49–0.78**：速度序列是强自相关的平滑过程（上一秒快下一秒也快），
  不是白噪声。我们生成器的 -0.23 说明存在"过冲-回拉"式的平滑振荡伪影。
- 配速 6'17"–7'31"（2.6–3.0 m/s）与校园跑要求区间吻合，可直接做校准目标带。

## 二、三方引擎深比

### 2.1 我们（TrackGenerator + FuckRunSim）

- 路线：围栏多边形约束 + 必经点途经 + 双阈值滤波（run 30 / gps 150，服务端实测值）
  + offFenceDisM 实算 + 摇杆实时模式。
- 步频：FuckRunSim 传感器级仿真（正弦加速度波，移植自 FUCK-RUN LSPosed 模块）。
- 优点：**申报一致性**（结算 distance 与几何一致）、字段保真（jadx 审计）、过滤语义对齐。
- 缺点（本轮实测坐实）：速度动力学贫乏——匀速 + 微抖，CV/自相关双双偏离真人。

### 2.2 ShandongTool（trajectory_engine.py，2211 行）

设计（文档自述 + 代码核实）：v(t) 单源物理模型——疲劳 U 型 + 1/f 慢漂移 + 逐点微抖 +
低频加减速事件，积分出坐标与步数；`cadence = 93.4·v^0.4683` 幂律闭合步频-步幅-配速
三角；accuracy 用 Gamma 采样（区间拒绝而非截断）；二分收敛目标距离；支持椭圆/田径场/
矩形三种跑法与真实停顿。

实测（3000m @ 450s/km，围栏 1.3~2.9km 见方，seed 42/7/2026）：
- 逐点 CV 0.39 / ac1 0.28~0.31 / 10s 窗 CV 0.29——动力学确实接近真人（略过冲）。
- **但申报 3000m、几何恒 5.3km（+77%）**：其阳光跑生成器把步态锁死在
  104 步/分 × 1.84m（真机观察值），时长 = 目标距离 ÷ 请求配速，两者独立 →
  请求配速 ≠ 315s/km 时几何与申报分裂。围栏尺度也影响收敛（官方示例围栏
  ~300m 时几何退化至 3m 仍申报 2006m）。
- 其自由跑引擎（generate_trajectory）自检距离误差 0.0、配速口径误差 0.3%——
  物理模型本身是好的，坏在阳光跑封装层。
- 真机口径字段（iOS HAR）：accuracy 仅 0/1/2、pois 7 字段、stepList 纯数字数组、
  公共参数无 channel、platform 数字——与 Android jadx 口径不同（我们按 Android，
  且已被真实服务端接受），是平台差异不是对错。

### 2.3 muccc526（GhostRunner）

恒速直线插值（3.34m/s 锁死）+ 围栏中心随机漫游，accuracy 1.0–3.0、satellites 12–22、
offFenceDisM 恒 -1、起点取围栏顶点。速度序列无动力学可言（CV≈0），但服务端不查所以能过。

## 五、v(t) 单源模型落地（2026-10-24 深夜追加）

§2.4 的改进路线已实现（`protocol.py` TrackGenerator）：

### 5.1 模型构成

```
v(t) = v₀ × [热身斜坡(0→78%起) × 疲劳衰减(末 35% 线性降到 86%)]
        × (1 + 1/f 慢漂移(±13%) + 中频节奏 OU(σ=20%, τ=12s)
             + 低频事件(0-2 次减速 72-90%、0-1 次冲刺 105-112%) + 微抖(1.2%))
弧长 s(t) = ∫v·dt —— 归一化保证 Σv·dt ≡ 目标距离（申报=几何的根基不动）
坐标 = 路线(椭圆/必经点环) 按弧长取点 + GPS 噪声
GPS 噪声 = 慢偏置游走(σ=1.5m, τ≈30s) + 小白噪声(σ=0.34m)   ← 两分量
```

关键教训（校准两轮才明白）：**白噪声 GPS 误差不能单独用**——它经差分进入
速度序列会带来 -0.5 的 lag-1 负自相关（相邻速度共享噪声项之差），而真人
是 +0.49~0.78。真实 GPS 误差是时间相关的（设备滤波、多径漂移）：慢偏置
分量相邻点间近似不变、差分后抵消，不产生负自相关；真速度方差主要由
中频节奏 OU（步频摆动）贡献——这才是同时满足「CV 高」与「自相关正」
的唯一组合。**负自相关是我们旧生成器的指纹级破绽**（真人不存在 -0.23）。

### 5.2 校准结果（30 种子 × 两种路径）

| 指标 | 真人带 | 椭圆路径 | 必经点路径 |
|---|---|---|---|
| 逐点速度 CV | 0.24–0.34 | **0.246** [0.218, 0.286] | **0.249** [0.217, 0.278] |
| lag-1 自相关 | 0.49–0.78 | **0.556** [0.445, 0.677] | **0.507** [0.404, 0.608] |
| 10s 窗配速 CV | 0.12–0.28 | **0.204** [0.171, 0.251] | **0.202** [0.169, 0.240] |
| 距离误差 | — | +0.80% | +0.15% |
| 最大点速 | <10.4 m/s | 4.6 m/s | 4.5 m/s |

距离膨胀 +0.8% 属 GPS 噪声的物理真实效应（真机 GPS 记录距离普遍虚高
1–5%），且远小于旧测试 3% 容差。
