# 闪动校园 · 安卓版 —— 接口契约（唯一权威）

> 本文件是 `projects/android/` 的**唯一契约来源**。三个实现方向（原生壳 / 前端 / 后端适配）
> 都必须严格照此实现，任何一方不得私自改方法名、参数顺序或返回结构。
> 参照物：桌面版 `projects/desktop/`（v2.0.0，功能与接口的**事实来源**）。

## 0. 目标与约束

| 项 | 约定 |
| --- | --- |
| 功能 | 与桌面版**完全一致**：登录/历史账号 → 选起始点 → 首页备跑 → 跑步页（摇杆实走 + 规划轨迹）→ 结束上传结算 → 账户记录 → 更多参数 |
| 接口 | 方法名、参数顺序、返回 JSON **逐字一致**（见 §2），前端 `bridge.js` 与 `scripts/android_check.py` 可原样复用 |
| 界面 | 按用户给的移动端线框图：竖屏四页（登录 / 选择起始点 / 首页 / 跑步） |
| 唯一交互差异 | 桌面版「跑步页按住鼠标右键拖拽规划复制点轨迹」→ 移动端改为**一个按钮在「摇杆」与「拖动」之间切换**（见 §4） |
| 协议/加密 | **零改动**。复用 `projects/desktop/shandong_school_cracked/` 整个包，不改业务逻辑 |

## 1. 架构

```
┌─────────────────────────────────────────────┐
│ MainActivity（唯一 Activity）                 │
│  └─ WebView（file:///android_asset/web/…）    │
│       ▲  window.SDAndroid.call(method, jsonArgs) │

│             └─ 复用桌面版 App 门面              │
```

- **Chaquopy 17.1.0**（MIT，全开源）+ **Python 3.12**（Chaquopy 的 Pillow 预编译 wheel 最高 cp313，3.12 最稳）。
- **AGP 8.13.2 / Gradle 9.3.1 / JDK 21**（本机已实测 `assembleDebug` 成功，含 Pillow）。
- minSdk **24**（Chaquopy 17.x 硬性下限）、targetSdk/compileSdk **36**、buildTools **36.0.0**。
- abiFilters：`arm64-v8a`（真机）+ `x86_64`（模拟器）。
- 前端：**React 18 + Leaflet**（去掉 antd，改自绘移动端组件），esbuild 打成单文件 `app.bundle.js`。
- 后端 Python 包以**整包复制**方式 vendoring 到 `app/src/main/python/shandong_school_cracked/`，
  只允许新增 `android_api.py` / `android_env.py` 与最小必要适配（见 §5），**不得改协议层**。

### 为什么不用 pywebview
pywebview 在 Android 无后端；Chaquopy 路线让**同一份 Python 业务代码**跑在手机上，
协议/仿真/存储零风险，符合「保持功能和接口一致」。

## 2. 桥接口（44 个方法，签名与桌面版 `gui.JsApi` 完全一致）

调用形式（两种，语义等价）：

```js
// 原生桥（Android 首选）：args 是 JSON 数组字符串，返回 JSON 字符串
window.SDAndroid.call("walk_joystick", "[0.5,0.5,0.8]")
// HTTP 降级（桌面版既有契约，保持兼容）
POST /api  {"method":"walk_joystick","args":[0.5,0.5,0.8]}
```

参数**按位置**传递，顺序与下表一致；所有返回值必须 JSON 可序列化。

## 4. 移动端交互：摇杆 / 拖动 切换（**本版本唯一的交互改动**）

桌面版：跑步页地图上**按住鼠标右键拖拽** → 从「人」的位置拉出复制点（ghost）轨迹，程序按轨迹驱动前进；推摇杆会清空计划改手动。

移动端没有右键，改为**一个切换按钮**（跑步页右下，紧邻「结束」）：`[ 摇杆 ] ←→ [ 拖动 ]`

- **摇杆模式（默认）**：显示摇杆控件（与桌面版同一套 `walk_joystick` 语义，触摸拖动产生方向与力度）；
  地图正常平移/缩放、**不**产生轨迹。推摇杆时清空已有计划轨迹（与桌面版一致）。
- **拖动模式**：隐藏摇杆；**单指在地图上按住拖动**即规划轨迹，逐条对齐桌面版 `onGhostStart/onGhostMove/onGhostEnd`：
  - 第一次拖动以当前「人」的位置为轨迹起点；再次拖动从**轨迹终点（复制点）**继续延长；
  - 用**相对位移**映射（`base + (cur - start)`），不是绝对取点；
  - 按「一秒步长 = speed 米」插值补点；60 ms 节流；
  - 松手结束本次拖动（`onGhostEnd`）；
  - 拖动期间禁用 Leaflet 地图平移（`map.dragging.disable()`），避免边规划边平移。
- 切回摇杆模式：**保留**已规划轨迹并继续自动沿轨迹走（与桌面版一致：只有推摇杆才清空）。
- 轨迹渲染：青色虚线 + 末端复制点圆；叠放层级与桌面版相同
  （围栏 < 起点 < 规划轨迹 < 轨迹 < 打卡点 < 复制点 < 人）。

## 5. 后端适配（只加不改）

`app/src/main/python/`：
- `shandong_school_cracked/` —— 从桌面版**整包复制**（不含 `gui.py`，移动端不用 pywebview）。
- `android_api.py` —— `dispatch(method:str, args_json:str) -> str`：白名单反射调用 `App` 门面，
  参数按 §2 顺序做类型强转（复刻 `JsApi` 的 `int()/float()/bool()/str()` 包装），异常返回
  `{"error":"<Type>: <msg>"}`；单例持有 `App`。
- `android_env.py` —— 平台注入点：
  - **数据目录**：由 Java 侧显式传 `<filesDir>/shandong-school_cracked`（不依赖 `Path.home()` 语义）。
  - **设备指纹**：Java 读 `Build.*` 传入，对齐原版语义
    （`modelName = Build.MANUFACTURER + "|" + Build.MODEL`、`systemVersion = Build.VERSION.RELEASE`、
    UA 品牌 = `Build.BRAND`，`UA = ShanDong/<versionName> (<BRAND>;Android <release>)`）。
    ★ **`platform` 必须显式回写常量值 `"2"`**（取值自 `constants.DEFAULT_PLATFORM`，
    即原版 `c31.java` 的 `i = "2"`，经 `r24.c(..., PLATFORM, ...)` 传入），
    **它是协议数字码，不是平台名**。
    反面案例（实测对真实服务端）：`platform="android"` → `code=1002 参数不合法`，
    登录在 `auth/loginCheck` 预检就挂；`platform="2"` → 正常。
    ⚠️ **不能写成「不管、交给默认值」**：`App.patch_config` 走 `_deep_merge`，
    历史版本曾把 `"android"` 写进 `config.json`，不显式覆盖就会让残留值永久生效
    （表现为升级后仍报 1002）。
    实现方式：**只允许**通过 `App` 已有的 config 通道（`patch_config`）注入，不改 `net.py`。
  - `open_url` / `quit` / `toast` 等需要 Android API 的动作：由 Java 注入回调
    （`android_env.set_host(host)` → Kotlin 实现 `HostBridge`）转发，**不要**在 Python 里 import android。
- Pillow：`captcha.py` 已 `try/except` 降级；Android 侧通过 Chaquopy `pip { install 'pillow==11.0.0' }`
  提供**真** Pillow（Chaquopy 有 `pillow-11.0.0-cp312-android_24_arm64_v8a.whl`），
  因此**滑块验证码在手机上可用**，与桌面版一致。

## 8. 验收标准

1. `./scripts/build_apk.sh` 产出可安装 APK（debug 签名即可）。
2. `scripts/android_check.py`：对**同一个 `android_api.dispatch`**（桌面 Python 直接 import 跑）
   走完 mock 全流程，断言 §2 全部方法可达且返回合法 JSON，口径与桌面版 `webcheck.py` 一致。
3. 前端 `Bridge.call` 覆盖 §2 每个方法至少一次（静态扫描断言，缺一个报错）。
4. 摇杆/拖动切换：两模式下 `walk_joystick` 与轨迹规划行为符合 §4。
5. 界面：四页版式对齐线框图，中文无乱码，地图瓦片正常加载。
